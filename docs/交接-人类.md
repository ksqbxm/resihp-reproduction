# ResiHP 复现 — 交接（人类版）

## 一句话

大模型训练中一张卡永久挂掉后，**不换卡、改拓扑**：用剩下的健康卡重新规划 TP/PP/DP，把失效卡上的
模型分片与优化器状态迁到幸存卡，从原进度继续训练。本仓库是这条纠错恢复路径的原生 PyTorch 复现
（微型 decoder-only Transformer + 真实通信 + 反复注入故障直到资源耗尽）。

```
8 卡 TP2×PP2×DP2 → rank1 fail-stop → 剩 7 卡：TP 降 degree / PP 重分层 / DP 重路由
→ 迁移 param、exp_avg、exp_avg_sq、step → 新拓扑继续训练
```

## 范围边界

做：纠错恢复（重规划 → 建群 → 状态迁移 → 继续训练）；fail-stop 是真 `SIGKILL`；原生 PyTorch +
NCCL/Gloo；FP32 + AdamW。
不做：Detector、心跳、fail-slow、速度启发式、性能优化、多卡同轮失效、多节点、Megatron。
所有存活设备一律视为健康（pᵢ≡1），论文的速度启发式在本项目中不存在（有门禁扫描全仓确保相关构造命中为 0）。

## 两条根本原则

**A 数值验收两段式**：恢复前，完整逻辑参数 + AdamW 状态与故障前 checkpoint `torch.equal`；
恢复后，与「同一 checkpoint 起点 + 新拓扑 + 新配置实际 batch + 同种子」的参考运行逐步一致。
基准是**新配置从同起点**，不是无故障从头跑——踢掉一个 rank 后 batch 划分与归约结构都变了。

**B 纯 fail-stop 确定性重路由**：DP 重路由是纯函数 `(step, failure_signature, active_topology) → assignment`，
不读运行时延迟、不看进度。`failure_signature` 由累计失效 rank 集合唯一确定。

## 环境

服务器上 Docker 容器 `resihp`（镜像 `resihp-env:gpu-fix-backup`，NVIDIA PyTorch 25.06 /
torch 2.8.0a0，CUDA 12.9.1，NCCL 2.27.3，8 卡全开）。代码 `/data/ubuntu/resihp-project`
bind mount 到容器 `/workspace/resihp`，宿主机 `git pull` 后容器内立刻可见。

```bash
docker start resihp && docker exec -it resihp bash
```

分支 `fix/dp-replica-level-rerouting`。跑多卡前先 `nvidia-smi` 确认卡空闲——历史上「NCCL 卡死」的
真实原因都是显存被别的进程占了。

## 怎么跑

```bash
python3 -m resihp.launch --config configs/train.json --failures configs/failures.json
```

入口不是 `torchrun`：elastic agent 见到 worker 被信号杀死会连带杀掉其余 worker，而这里要的是
幸存者原地重配。`resihp.launch` 托管 TCPStore、起 worker、子进程死掉时不动其余进程、汇总退出码。

`configs/train.json` 字段是封闭集合（少一个报缺失，多一个报未知字段，无默认值兜底）：
`model_dim / num_layers / num_heads / batch_size / micro_batch_size / seed / tp / pp / dp /
iterations / memory_budget_bytes`。`memory_budget_bytes` 是唯一可选字段（`null` = 不设上限）。

`configs/failures.json` 只允许 `after_iteration`（严格递增）与 `failed_rank`（不重复）。
出现速度/降级/检测类字段直接拒绝并报字段名。

跑完每个存活 rank 打印一行 `{"acceptance": {...}}`（含 `trained_iterations`、`plan_versions`、
`plan_digests`、`failed_ranks`），一致停止则打印 `{"stopped": "<code>", ...}`。退出码证明不了
「故障真发生过而且训练继续了」，这行 JSON 才是可外部验证的证据。默认配置排了五次连续 fail-stop，
让 TP（降 degree）、PP（搬层/清空 stage）、DP（重路由 micro-batch）三个维度都真的动起来。
